# Elemental Shaman investigation (issue #11)

This is a handoff, not a working spec. The committed `ele` core reference is
Farseer and reports 161,887.75 DPS. Ancestor Lava Burst accounts for 17.49%
and ancestor Elemental Blast for 2.35% of that total. It reports 282.57 and
42.45 hits per fight respectively; these counts must be generated by mechanics,
not fitted by calibration.

SimC's `sc_shaman.cpp`, `shaman_t::trigger_ancestor`, iterates over every
active ancestor when a qualifying owner spell impacts. Normal Lightning Bolt
and Lava Burst both select the ancestor Lava Burst action. Ancestor Lava Burst
always crits and its action multiplier also scales with crit chance. An
ancestor's expiration can fire Elemental Blast via Final Calling and can
summon another ancestor via Ancient Fellowship. Stormkeeper summons an ancestor
and, with Fury of the Storms, a storm elemental. The rotation is in
`ActionPriorityLists/default/shaman_elemental.simc` (single-target section).

The existing pet engine has per-instance lifetimes and expiration effects,
but the ordinary `trigger` effect executes once, not once per active pet. A
generic effect that executes a pet action for each active instance, preserving
pet context and named RNG streams, is a candidate for modelling this. Verify
its interaction with simultaneous expiration, nested summons and owner casts
before calibrating. The ancestor's extra crit scaling also needs to be retained
when comparing the crit probe. Lava Surge during a Lava Burst cast has special
consumption handling in SimC and needs separate investigation.

`tools/db2.py --build 12.1.5.70575` fetched its declared tables, but
`tools/spelldb.py` additionally requires SpellCooldowns, SpellCategories,
SpellCategory, SpellPower, SpellAuraOptions and SpellDuration CSVs, which the
former does not fetch. Obtain those tables before relying on spell lookup.

Baseline on commit `c4b90fe`, release build, 2,000 iterations and seed 1:
Retribution 132,853 DPS, Fire 148,216, Destruction 155,722, Subtlety 181,376
(CLI-rounded values). Preserve full command output when making engine changes;
rounded values alone cannot establish bit-for-bit equality. No engine or spec
changes were made in this investigation.
